# SoulLog Backend

Django + DRF + Channels + PostgreSQL API for SoulLog — a private wellness
journaling app with an optional, carefully scoped social layer.

## Status

This is a real, tested backend, not a mock. Everything listed below is
wired to the actual React frontend and covered by automated tests. See
`docs/NOT-BUILT-OR-DEFERRED.md` for an honest account of what remains —
including the things that were decided against rather than postponed.

**Built and tested:**

- **Auth** — register, login, JWT refresh, password reset (no account
  enumeration), change password, account deletion with cascade, data
  export
- **Journaling** — CRUD, privacy enforcement, photo and voice
  attachments, comments and replies, reactions, and all four share
  settings (`identity`, `include_mood`, `include_date`, `allow_comments`)
  enforced rather than merely stored
- **Mood check-ins** — the exact 12-mood vocabulary the UI offers
- **Insight Engine** — six analyzers, computed live from the user's own
  data, silent when the data doesn't support a claim
- **Dashboard stats** — entries, streak, insights, community posts, mood
  check-ins, with documented and tested business rules
- **Settings** — full persistence across three models in one payload
- **Connections** — request/accept/decline/block state machine, one-way
  follows kept separate, ranked suggestions whose stated reasons are true
- **Notifications** — creation, storage and delivery separated (spec
  §89), generated by real actions, respecting each user's own toggles
- **Whispers** — conversations, messages, attachments, read state, with
  live delivery and typing over WebSockets
- **Sanctuary** — the shared feed, with media, comments, reactions,
  bookmarks and shares
- **Content library** — uploads or external links, real view/like/save
  counts, progress tracking
- **Community** — discovery across people, posts and content, with real
  recent and trending searches

**Not built:** voice and video calling, an achievements model,
profile-view tracking, sleep and weather insights, payments, and full
groups. Each with its reasoning in `docs/NOT-BUILT-OR-DEFERRED.md`.

## Quick start

See `../SETUP.md` for exact, verified commands and troubleshooting.

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # set SECRET_KEY and DB_PASSWORD
python manage.py migrate
python manage.py runserver
```

`runserver` serves ASGI (Daphne is first in `INSTALLED_APPS`), so
WebSockets work in development without a second process. Redis is not
needed locally — without `REDIS_URL` the in-memory channel layer is used.
It becomes required as soon as the backend runs more than one worker.

## Demo data

```bash
python manage.py seed_demo         # six accounts with six weeks of history
python manage.py audit_demo_data   # prove it's exactly what it claims to be
python manage.py clear_demo        # remove all of it, and only it
```

## Tests

```bash
python manage.py test
```

178 tests, covering auth, privacy enforcement, connection and block
rules, notification suppression, messaging permissions, feed visibility,
upload validation, profile visibility, and Insight Engine restraint —
plus real WebSocket tests that assert the socket enforces the same
permissions the HTTP endpoints do.
